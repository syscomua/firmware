# Задание для агента: лента «Избранные каналы» в Telegram для Android

## Контекст

- Исходники клиента подключены сабмодулем `telegram-android/`
  (форк `syscomua/Telegram` от апстрима `DrKLO/Telegram`, версия 13.1.1 (7237)).
- Сначала: `git submodule update --init --depth 1 telegram-android`.
- Код приложения: `telegram-android/TMessagesProj/src/main/java/org/telegram/`
  (`messenger/` — логика и хранилище, `ui/` — экраны, `ui/Cells`, `ui/Components`).
- Работайте в сабмодуле на отдельной ветке. Апстрим-файлы трогайте минимально:
  новую логику кладите в новые классы, в существующие добавляйте только точки подключения.
  Так проще подтягивать обновления апстрима.

## Цель

Пользователь отмечает каналы как «избранные». В отдельном месте приложения есть
**единая лента**: все посты из избранных каналов в хронологическом порядке
(сначала новые), как в лентах соцсетей.

## Функциональные требования

### 1. Отметка канала как избранного
- Пункт меню «Добавить в избранную ленту» / «Убрать из избранной ленты»:
  - в меню (⋮) профиля канала: `ui/ProfileActivity.java`;
  - в меню (⋮) экрана канала: `ui/ChatActivity.java`;
  - в действиях при долгом нажатии на канал в списке чатов: `ui/DialogsActivity.java`.
- Пункт показывается только для **каналов** (`ChatObject.isChannelAndNotMegaGroup(chat)`),
  а не для групп, супергрупп, ботов и личных чатов.
- Избранный канал помечается значком (звёздочкой) в `ui/Cells/DialogCell.java`.

### 2. Хранение
- Новый класс `messenger/FavoriteChannelsController.java`, по одному экземпляру на
  аккаунт: наследник `BaseController`, `getInstance(int account)`, как у других контроллеров.
- Список избранных хранится локально, отдельно для каждого аккаунта. Подойдёт новая
  таблица `favorite_channels(did INTEGER PRIMARY KEY, added_date INTEGER)` в
  `MessagesStorage` с миграцией (`LAST_DB_VERSION` сейчас 179; поднять номер версии и
  добавить шаг миграции в `updateDbToLastVersion`). Допустим и вариант с
  `SharedPreferences`, но тогда это нужно обосновать.
- Изменения рассылаются через новое событие `NotificationCenter`,
  например `favoriteChannelsUpdated`.
- Если пользователь отписался от канала или потерял к нему доступ, канал остаётся
  в списке, но не участвует в ленте и выделен в настройках.

### 3. Экран ленты
- Новый `ui/FavoriteFeedActivity.java` (наследник `BaseFragment`).
- Точки входа:
  - новая вкладка «Лента» в нижней навигации `ui/MainTabsActivity.java`
    (в 13.x основная навигация сделана нижними вкладками; фрагмент реализует
    `MainTabsActivity.TabFragmentDelegate`, как это делает `DialogsActivity`);
  - (опционально) системная вкладка-папка в верхних табах папок `DialogsActivity`.
- Содержимое:
  - посты из всех избранных каналов, отсортированные по `date` (по убыванию);
  - у каждого поста заголовок с аватаром и названием канала, тап по нему открывает канал;
  - пост показывается переиспользованием `ChatMessageCell` / `MessageObject`
    (текст, фото, видео, альбомы, опросы, ссылки, реакции, счётчик просмотров);
  - тап по посту открывает `ChatActivity` канала на этом сообщении (`scrollToMessageId`);
  - бесконечная прокрутка вниз (подгрузка старых), pull-to-refresh сверху;
  - новые посты появляются вверху сами (подписка на `didReceiveNewMessages`)
    с плашкой «N новых постов»;
  - удаление и редактирование постов отражается в ленте
    (`messagesDeleted`, `replaceMessagesObjects`);
  - пустое состояние с подсказкой, как добавить канал;
  - меню экрана: «Управление каналами» (список избранных с удалением),
    «Отметить всё прочитанным».

### 4. Загрузка данных (ключевая часть)
Серверного метода «лента из набора каналов» нет, поэтому лента склеивается на клиенте:
- Для каждого канала нужен курсор `(dialogId, minLoadedId, minLoadedDate, hasMore)`.
- Начальная загрузка: из каждого канала берётся по N последних сообщений
  (сначала из локального кэша `MessagesStorage`, потом из сети `TL_messages_getHistory`).
  Дальше k-way merge по дате, на экран выдаётся первая страница.
- Подгрузка вниз: догружать только те каналы, чей курсор оказался выше нижней
  границы текущей страницы. Иначе порядок постов будет неверным.
- Запросы ограничены по параллельности (например, не больше 3–4 одновременно),
  на `FLOOD_WAIT` нужна обработка с backoff.
- Сервисные сообщения (закреп, смена фото и т. п.) в ленту не попадают.
- Альбомы (`grouped_id`) собираются в один элемент, как в `ChatActivity`.
- Логику merge вынести в отдельный класс без зависимостей от Android
  (например, `FavoriteFeedMerger`), чтобы её можно было покрыть unit-тестами.

### 5. Прочитанность и уведомления
- При показе поста в ленте канал помечается прочитанным до этого id
  (`MessagesController.markDialogAsRead`). Поведение отключаемое, по умолчанию включено.
- Бейдж непрочитанного на вкладке «Лента» = сумма `unread_count`
  избранных каналов.
- Отдельные уведомления — вне рамок этой итерации.

### 6. Локализация
- Все строки добавить в `TMessagesProj/src/main/res/values/strings.xml`,
  обращаться к ним через `LocaleController.getString(R.string.X)`.
- Дать переводы хотя бы на русский и украинский (`values-ru`, `values-uk`).

## Нефункциональные требования
- Без лишних блокировок UI-потока: работа с БД на `MessagesStorage.getStorageQueue()`,
  результаты в UI через `AndroidUtilities.runOnUIThread`.
- Корректная работа при нескольких аккаунтах (`currentAccount`).
- Поддержка тёмной и светлой темы через `Theme.key_*`.
- Сборка проходит: `./gradlew :TMessagesProj_App:assembleAfatDebug`
  (для сборки нужен собственный `api_id`/`api_hash` в `BuildVars.java`,
  их нельзя коммитить).

## Этапы (каждый — отдельный коммит/PR)
1. `FavoriteChannelsController` + миграция БД + событие NotificationCenter + unit-тесты.
2. Пункты меню «в избранное» (профиль, чат, список чатов) + значок в `DialogCell`.
3. `FavoriteFeedMerger` (чистая логика) + unit-тесты сценариев merge и пагинации.
4. `FavoriteFeedActivity`: первая страница, пагинация, открытие поста, пустое состояние.
5. Live-обновления (новые, удалённые, отредактированные посты), pull-to-refresh, прочитанность.
6. Вкладка в `MainTabsActivity` + бейдж, экран управления списком, локализация.

## Критерии приёмки
- Можно отметить или снять отметку с канала из трёх мест. Отметка сохраняется после
  перезапуска и не видна в другом аккаунте.
- Лента показывает посты из всех избранных каналов строго по убыванию даты,
  без дублей и пропусков при прокрутке на 200+ постов вглубь.
- Новый пост в избранном канале появляется в ленте без перезапуска экрана.
- Удалённый или отредактированный пост обновляется в ленте.
- Тап по посту открывает канал на нужном сообщении.
- Unit-тесты merge/пагинации проходят. Приложение собирается.
